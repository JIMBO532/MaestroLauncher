## Microsoft / Xbox / Mojang authentication
- Live device code: POST https://login.live.com/oauth20_connect.srf
  body client_id=00000000402b5328&scope=service::user.auth.xboxlive.com::MBI_SSL&response_type=device_code
  → HTTP 200 JSON keys: device_code, user_code, verification_uri ("https://www.microsoft.com/link"),
  expires_in (900), interval (5).
- Live token poll: POST https://login.live.com/oauth20_token.srf
  body client_id=...&device_code=...&grant_type=urn:ietf:params:oauth:grant-type:device_code
  → while pending: HTTP **400** with JSON {"error": "authorization_pending", "error_description": "..."}.
  Parse the JSON body on 4xx; a 400 here is NOT a transport failure. Success: HTTP 200
  {"token_type", "expires_in", "scope", "access_token", "refresh_token", "user_id"}.
- Entra device code: POST https://login.microsoftonline.com/consumers/oauth2/v2.0/devicecode
  body client_id=...&scope=XboxLive.signin offline_access → 200 {"user_code", "device_code",
  "verification_uri" ("https://microsoft.com/devicelogin"), "expires_in", "interval", "message"};
  errors are HTTP 400 {"error", "error_description"} (observed "unauthorized_client" for a bogus id).
- Entra token poll: POST .../consumers/oauth2/v2.0/token
  body grant_type=urn:ietf:params:oauth:grant-type:device_code&client_id=...&device_code=...
  → pending = HTTP 400 {"error": "authorization_pending"}; also "slow_down", "expired_token",
  "authorization_declined", "bad_verification_code".
- Refresh: Entra → POST .../consumers/oauth2/v2.0/token
  grant_type=refresh_token&refresh_token=...&client_id=...&scope=XboxLive.signin offline_access.
  Live → POST https://login.live.com/oauth20_token.srf
  grant_type=refresh_token&refresh_token=...&client_id=00000000402b5328&scope=service::user.auth.xboxlive.com::MBI_SSL.
- XBL: POST https://user.auth.xboxlive.com/user/authenticate JSON
  {"Properties": {"AuthMethod": "RPS", "SiteName": "user.auth.xboxlive.com", "RpsTicket": "<prefix><access_token>"},
   "RelyingParty": "http://auth.xboxlive.com", "TokenType": "JWT"}
  → {"Token", "DisplayClaims": {"xui": [{"uhs"}]}}.
  RpsTicket prefix: "d=" for Entra-issued tokens, "t=" for Live legacy (MBI_SSL) tokens. This is the
  documented community convention and cannot be verified without a real sign-in — keep it in one
  named constant per mode so it is a one-line change.
- XSTS: POST https://xsts.auth.xboxlive.com/xsts/authorize JSON
  {"Properties": {"SandboxId": "RETAIL", "UserTokens": ["<xbl token>"]},
   "RelyingParty": "rp://api.minecraftservices.com/", "TokenType": "JWT"}
  → {"Token", "DisplayClaims": {"xui": [{"uhs", "xid"}]}}.
  HTTP 401 body: {"XErr": 2148916233, "Message": "", "Redirect": "https://start.ui.xboxlive.com/..."}.
- Mojang: POST https://api.minecraftservices.com/authentication/login_with_xbox
  {"identityToken": "XBL3.0 x=<uhs>;<xsts token>"} → {"username", "roles", "access_token",
  "token_type", "expires_in" (86400)}.
- Profile: GET https://api.minecraftservices.com/minecraft/profile (Bearer) → 200
  {"id": "<32 hex chars, no dashes>", "name", "skins", "capes"}; 404 = does not own Java Edition;
  401 = expired token; 403 = something else.
